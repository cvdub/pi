** What to build
Add a backward-compatible ACP projection contract to Pi's coding-agent tool definitions and honor it in both live tool-call mapping and session history replay. A tool may synchronously derive ACP result content from its persisted result and error status, override its standard ACP kind, and opt out of ACP raw input or raw output. The projection must remain separate from provider-agnostic model results, require no persisted schema change, fail closed to bounded client content, and preserve current behavior for tools without declarations.

Document the extension-facing contract and ACP behavior in this repository. Complete the capability and its focused tests without implementing a policy for any particular extension; downstream repositories can adopt a tested Pi revision and the generic contract independently.

*** Goal
Expose a generic, backward-compatible ACP presentation seam on coding-agent tool definitions, and apply the current definition consistently to live tool events and persisted-history replay without changing model-facing results or session schemas.

*** Dependencies and data structures
Use the existing pinned =@agentclientprotocol/sdk= =ToolKind= type and the existing Pi =AgentToolResult= plus text/image content block types; no new dependency is needed. Extend =ToolDefinition<TParams, TDetails, TState>= with =acpResultContent(result: AgentToolResult<TDetails>, options: { isError: boolean }): (TextContent | ImageContent)[]=, static =acpKind?: ToolKind=, and literal-false =acpRawInput?: false= / =acpRawOutput?: false=. The hook is synchronous and its documented interface requires deterministic derivation from the supplied persisted result and error status; an empty array intentionally suppresses terminal ACP content.

*** Module seams and data flow
Keep =AcpToolCallMapper= as the live presentation module and inject a current-definition resolver through =AcpToolCallMapperOptions=, supplied by =AcpSessionRegistry= from =runtime.session.getToolDefinition=. Resolve declarations when announcing, projecting cumulative snapshots, and projecting terminal results. Centralize result projection in =tool-call-mapper.ts=: invoke a declaration when available, convert its Pi blocks through the existing bounded ACP conversion, and on exception log the underlying failure outside the protocol stream while returning only a fixed short diagnostic. Preserve input-derived successful edit/write diff precedence; undeclared or unresolved tools use the existing bounded model-result projection.

Store only live per-call presentation state needed for consistent terminal updates. Announcements use the declaration's =acpKind= before name inference and omit =rawInput= only for literal false. Terminal updates omit =rawOutput= for literal false and fail-closed projection diagnostics while retaining complete execution/session data internally. Projection never mutates the =AgentToolResult=.

Inject the same resolver into =streamSessionHistory= / =buildHistoryUpdates=. Replay resolves each tool name against the currently installed definition and applies the same content, kind, raw-field, error, and fallback helpers while deriving everything from existing assistant/tool-result messages. Missing definitions remain replayable through the current bounded defaults.

** Notes
The delivery contract is the Effort spec. A downstream dotfiles Effort owns the first deployed consumer: compact ACP presentation for its subagent extension, the Pi package revision handoff, Guix Home integration, and Agent Shell acceptance.
